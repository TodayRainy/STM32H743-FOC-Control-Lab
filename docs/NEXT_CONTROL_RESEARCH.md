# 下一轮控制算法研究方向

更新时间：2026-08-30

本文以D-080统一速度/位置域验证为入口，只选择当前硬件能够形成“设计—实现—实测—判退”闭环的课题。它不是功能清单，也不要求按编号机械执行。

## D-082/D-083执行结论

两条建议主线均已闭环，不再作为开放待办：

- ABZ的4计数周期估计、10 ms停转归零及100～250 rpm WIN融合已经实现。纯量化回归在50 rpm降低约29%误差RMS，但真实双向±25/±50/±100 rpm闭环的速度误差RMS和`iq_ref` RMS平均分别增加3.09%和0.95%；18/20次机械谐波变化也不一致。FUSED保留为可选研究模式，默认继续WIN。
- 单轴解析jerk受限S曲线已经实现，400 Hz下1°/5°/90°分别覆盖4/6/7段，运行中重定向只保留最新目标并在当前点到点轨迹结束后执行。双轮反序52行程全部通过稳态误差，但相对TRAP总体时间增加2.67%，电流和跟踪指标相当，最坏区域过冲未改善。SCURVE保留可选，默认继续RAMP。

这两项的判退说明当前主要限制已不是缺少一个新滤波器或参考整形器。后续若继续机器人控制，应等待独立速度/转矩真值或受控负载后研究机械扰动；当前可先推进命令看门狗、故障快照导出以及电源可调后的欠压TRIP。

## 当前证据给出的优先级

D-080已经把现有控制链的边界分开：

- ABZ速度环在双向250～6500 rpm及零速保持通过，±50/±100 rpm均值误差仍小于0.7 rpm，但误差RMS为17.10～22.36 rpm；问题是低速瞬时速度质量，而不是PI直流跟踪失效。
- 默认位置RAMP的13/13点和可选TRAP+速度前馈的5/5点全部通过，最大稳态误差RMS为0.8025°。位置环已可用，但轨迹只约束速度或速度/加速度，尚没有跃度约束。
- HFI/Active Flux 14/14保持点和4/4来源切换通过；I/f启动后的Active Flux双向500～6500 rpm通过。无感主链当前不缺新的默认观测器。
- eSMO影子可靠下限为正向1000 rpm、反向1500 rpm，明显晚于Active Flux双向500 rpm，不适合作为当前默认控制源。
- HYBRID弱磁在固定±6500 rpm、`VOLT LIMIT 1.00→0.45→1.00`四次访问全部通过；当前缺口是真实母线扰动、负载和热边界，不是更多人工比例点。

因此下一轮建议先做“低速测速”，再做“单轴机器人轨迹”。这两项都能在现有24 V空载平台上得到直接量化证据。

## 成熟实现的共同结构

### 状态、故障和控制源

ST MCSDK把IDLE、START、SWITCH_OVER、RUN、STOP和FAULT状态明确分开；故障存在与故障消失后的等待确认也分为不同状态。它同时把速度/位置反馈抽象为共同接口，再由编码器或观测器实现。当前项目的`lifecycle + operation + rotor_source + diagnostic`与这个方向一致，不需要重新改成单一巨大枚举。[ST MCSDK状态机与故障说明](https://www.st.com/resource/en/user_manual/um3042-stm32-motor-control-sdk--6step-firmware-library-stmicroelectronics.pdf)、[ST Motor Control Workbench反馈源说明](https://wiki.st.com/stm32mcu/wiki/STM32MotorControl%3ASTM32_MC_Workbench)

ODrive同样让状态请求由轴状态机消费，并独立保留编码器、传感器无感估计器、开环启动、控制器和轨迹模块；其接口还提供通信看门狗、任务耗时、端点和错误位。当前工程已经有相同的骨架，后续只应补实际需要的状态，不再做目录级重构。[ODrive官方接口定义](https://github.com/odriverobotics/ODrive/blob/master/Firmware/odrive-interface.yaml)

VESC长期演进也把HFI、开环同步、磁链跟踪观测器、编码器/无感切换和故障代码作为独立能力维护，并明确记录了编码器滑移、超速/欠速、观测器磁链跟踪和HFI歧义处理。它说明成熟方案依赖清楚的来源管理与可观测诊断，而不是让多个观测器同时争夺控制权。[VESC官方固件变更记录](https://github.com/vedderb/bldc/blob/master/CHANGELOG.md)

### 低速编码器测速

TI eQEP把“单位时间计数”与面向低速的QCAP周期测量并列提供，同时有停转监测。这正对应D-080的结果：1 ms WIN在中高速带宽合适，但低速瞬时量化和机械纹波过大；只继续加大速度PI或改滤波截止频率不会增加低速边沿时间信息。[TI eQEP官方驱动说明](https://software-dl.ti.com/C2000/docs/f29h85x-sdk/latest/docs/html/DRIVERS_EQEP_PAGE.html)

### 轨迹与前馈

ODrive提供梯形轨迹，moteus把位置/速度命令、速度和加速度限制、惯量加速度前馈、跟踪误差与超时策略分别配置。当前项目已有RAMP、TRAP和速度前馈，因此更合理的增量是加入单轴跃度限制，而不是再扫位置P。[moteus官方配置说明](https://github.com/mjbots/moteus/blob/main/docs/reference/configuration.md)、[ODrive官方接口定义](https://github.com/odriverobotics/ODrive/blob/master/Firmware/odrive-interface.yaml)

Ruckig给出了成熟的实时限跃度轨迹参考，但本项目只有单轴且强调紧凑实现；下一轮应借鉴其状态量和约束语义，不直接引入完整多轴库。[Ruckig官方仓库](https://github.com/pantor/ruckig)

## 建议主线A：ABZ低速计数/周期融合测速

### 目标

保持当前WIN在250～6500 rpm的已验证表现，同时降低±50/±100 rpm速度误差RMS，不改D-043速度PI。

### 最小设计

1. 保留TIM3的4096计数机械角和现有WIN输出。
2. 先做一次只读硬件可行性验证，确认TIM3编码器模式下能否取得A/B边沿时间戳或以并行EXTI/DMA记录边沿；不先改CubeMX或占用现有MT6835 PWM的TIM2输入捕获。
3. 形成周期支路：有新边沿时按有符号计数增量/边沿间隔估速；无边沿超过停转门槛时平滑归零。
4. 按边沿频率在周期支路和现有1 ms WIN间做一次连续权重融合。只保留一个输出滤波器和一组切换带，不引入多层质量状态。
5. 继续使用现有速度PI；只有测速改善后仍出现明确闭环反例，才讨论低速专用PI。

### 验证与退出

- 离线用实际ABZ计数回放验证方向反转、计数回绕和停转；
- 板端只跑0、±25、±50、±100、±250、±500 rpm及一次正反连续穿零；
- 主要指标为均值偏差、速度误差RMS、穿零延迟、峰值dq电流和250/500 rpm对现有WIN的非劣化；
- 若拿不到真实边沿时间戳，或周期支路在±50/±100 rpm不能稳定优于当前17～22 rpm RMS，则停止该硬件路径，不用更多滤波层掩盖信息不足。

## 建议主线B：单轴限跃度位置轨迹

### 目标

在不改位置P、速度PI和电流PI的前提下，让位置参考同时具备连续速度和连续加速度，降低启停冲击并形成更接近机器人关节的运动接口。

### 最小设计

- 在现有`TRACK_MODE`中增加单轴S曲线模式，状态只保存位置、速度、加速度、目标和三个限制；
- 先实现静止到静止的对称限跃度点到点，不移植多轴同步、路径点队列或通用规划框架；
- 速度前馈继续使用轨迹速度；加速度前馈接口可以预留在算法输出中，但在没有可信惯量前默认不进入q轴电流；
- START POSITION仍清除内速度轨迹，状态机归属不变。

验证复用±1、±2.2、±5、±30、±90、±360°矩阵，比较TRAP与S曲线的峰值速度、峰值dq电流、端点过冲、整定时间和参考加速度连续性。若只改善参考波形而控制指标无可重复收益，则保留TRAP默认，不继续扩展跃度网格。

## 第二优先级：完成控制面而非增加控制器

以下项目成熟且有工程价值，但排在上述两条控制主线之后：

1. **可选命令看门狗**：只对需要持续上位机更新的模式启用，超时执行可配置STOP或受限减速；静态目标模式默认不启用。ODrive和moteus都提供该语义。
2. **跟踪误差诊断收口**：现有速度/位置WARNING已具备活动、恢复、锁存和确认。下一步只补GUI阈值显示与首次快照导出，不增加不能实测的温度、母线电流或缺相故障。
3. **受控欠压TRIP**：等电源可调时单独完成`FAULT_ACTIVE→FAULT_LATCHED→CLEAR`和PWM停机验证；不与算法矩阵混跑，也不用过流、过压或超速代替。
4. **配置持久化**：等控制参数集合稳定后再做版本化参数块；当前不建立插件、固件升级或通用对象字典。

## 暂不进入主动路线的算法

- **DOB/ESO、摩擦和齿槽补偿**：没有可控扰动或转矩真值时无法区分控制收益与当前机械区域差异。D-048/D-054也不支持直接生成可靠补偿表。
- **MTPA/MTPV和效率优化**：空载平台不能验证同转矩最小电流、轴功率或效率。
- **在线Rs/磁链跟踪**：VESC等成熟固件已经采用，但当前缺温度和负载跨度；先保留影子估计研究入口，不写入默认模型。
- **eSMO接管控制**：D-080已经证明其双向可靠下限晚于Active Flux，除非后续模型或离散实现有明确改进，不做默认源A/B。
- **过调制、再生功率和热降额**：当前没有母线电流、温度和可吸收再生能量的测试平台，不能形成安全的闭环结论。

## 推荐推进顺序

1. D-082/D-083结果作为现役判退基线，不再重复扫描测速滤波或jerk参数；
2. 讨论并冻结可选命令看门狗与首次故障快照导出范围；
3. 电源可调后单独补欠压TRIP；
4. 只有获得受控负载、独立速度/转矩或温度测量后，再恢复DOB/ESO、摩擦/齿槽、MTPA或在线参数跟踪。
