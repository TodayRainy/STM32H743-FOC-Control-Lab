# 关键决策记录

这里记录会影响后续工作的技术和协作决策。状态分为“采用”“待复核”“已替代”。新证据可以改变决定，但应保留原因和替代关系。

## D-001：算法研究优先于低价值工程重构

- 日期：2026-08-24
- 状态：采用
- 决定：在三环基础可用的前提下，优先参数辨识、自整定、MTPA/弱磁和无感控制；回归验证与风险相称。
- 原因：老代码已长期运行，项目目标是控制专业秋招展示，主要价值来自方法、实验和量化对比。
- 复核条件：出现基础安全、内存、实时性或数据正确性问题时，先处理阻塞问题。

## D-002：不开展死区补偿修改

- 日期：2026-08-24
- 状态：采用
- 决定：现阶段不修改死区相关代码。
- 原因：死区由栅极驱动芯片处理，现有代码运行未出现明确安全问题，且没有物理示波器验证功率波形。
- 复核条件：更换栅极驱动/功率级，或获得波形证据表明死区造成可测控制误差。

## D-003：不把硬件 BRK 作为当前方案

- 日期：2026-08-24
- 状态：采用
- 决定：不重复规划比较器到定时器 BRK 的硬件保护。
- 原因：当前硬件没有比较器，无法实现该链路。
- 复核条件：硬件改版加入比较器或驱动芯片提供可接入故障输出。

## D-004：串口主观测，J-Link 后备观测

- 日期：2026-08-24
- 状态：采用
- 决定：运行命令、遥测和批量实验以串口为主；J-Link 用于烧录、在线调试和串口不可用时读取内存示波器。
- 原因：串口适合连续大量数据，J-Link 在端口故障时仍可读取 SRAM。
- 复核条件：虚拟串口再次长期不可用，或引入更合适的 CAN/高速 USB/RTT 通道。

## D-005：项目默认使用 J-Link V7.54d

- 日期：2026-08-24
- 状态：采用
- 决定：默认使用 C:\Program Files\SEGGER\JLink\JLink.exe，即 V7.54d。
- 原因：用户明确选择该版本，并已完成实际连接和烧录验证。
- 已知冲突：个人 J-Link Skill 当前 preferred backend 指向 CubeProgrammer 的 V7.92o DLL。
- 后续动作：在单独的工具配置任务中消除默认后端冲突；此前每次显式指定 V7.54d。
- 复核条件：V7.54d 出现可复现缺陷，且新版本经过同板验证。

## D-006：不把 COM 号写死在固件

- 日期：2026-08-24
- 状态：采用
- 决定：COM 号只属于被忽略的主机配置或命令参数，不进入固件和发布文档。
- 原因：设备重新枚举后 COM 会变化。
- 复核条件：未来使用稳定设备标识自动匹配时，可替换人工端口参数，但仍不写入固件。

## D-007：保留高可观测性，不精简队列和数据

- 日期：2026-08-24
- 状态：采用
- 决定：功能完善阶段不为了表面整洁减少调试队列、遥测或有价值的数据。
- 原因：当前研究需要观察大量控制信息，更多证据有助于辨识和算法比较。
- 复核条件：量化证明内存、实时性或传输带宽成为阻塞后，再有针对性优化。

## D-008：采用内存软件示波器

- 日期：2026-08-24
- 状态：采用
- 决定：FOC ISR 只向 D2 SRAM 缓冲记录数据，捕获完成后通过串口或 J-Link 导出。
- 原因：不能在 40 kHz 中断内持续发送串口；当前实现开销约为 FOC 周期 1.03%，能够支撑后续研究。
- 限制：只能观察软件变量，不能替代功率级物理示波器。
- 复核条件：新算法需要更长记录、更高通道数或触发机制时，按需求扩展。

## D-009：一次上电尽量执行连续测试

- 日期：2026-08-24
- 状态：采用
- 决定：在安全工况内，把多个电流、速度、位置和算法开关点合并为一次自动化测试。
- 原因：反复人工上电、断电降低效率。
- 边界：自动化不扩大用户批准的电流、速度和动作范围；异常时立即停止。

## D-010：路线图采用能力依赖而非固定工期

- 日期：2026-08-24
- 状态：采用
- 决定：共享主干依次强化观测、基线、辨识和自整定，再按机器人或新能源方向分支；阶段允许并行、回退或调整。
- 原因：当前只有空载和软件观测条件，很多研究结果会影响后续路线，写死顺序会妨碍合理探索。
- 复核条件：项目进入明确的答辩、比赛或秋招交付窗口后，再增加时间和范围约束。

## D-011：文档分层，AGENTS.md 保持精简稳定

- 日期：2026-08-24
- 状态：采用
- 决定：永久规则、动态状态、路线图、工具链、工作流、决策和实验数据分别存放。
- 原因：降低长对话、上下文压缩和 Skill 默认配置造成的状态混淆。
- 复核条件：某一模块形成独立且稳定的特殊规则时，可以增加局部 AGENTS.md；当前不需要。

## D-012：不过度防御

- 日期：2026-08-24
- 状态：采用
- 决定：只针对已观察风险、明确接口契约或高概率故障加入必要保护，不嵌套多层预见性防御代码。
- 原因：过度防御会掩盖控制主线、增加状态空间和调试成本。
- 边界：中断安全、电流/速度限幅、STOP、内存越界和烧录确认属于直接必要保护，不视为过度防御。

## D-013：不持久化当前上电状态

- 日期：2026-08-24
- 状态：采用
- 决定：任何文档和 state.json 都不能被解释为“现在仍上电”。硬件操作前以用户当次确认优先。
- 原因：电源、USB 和电机状态会在窗口之间变化，旧状态是最危险的上下文污染之一。
- 复核条件：未来存在可被软件可靠读取且具备安全语义的电源控制器时，再设计自动状态检查。
